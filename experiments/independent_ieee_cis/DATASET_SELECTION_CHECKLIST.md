# Dataset-selection checklist (for IEEE-CIS now, and for any fallback)

No dataset below was verified; current availability, licence and content must be checked by the owner on the official source. Web access to the official hosts was not available in this session.

| # | Criterion | Why it matters here | IEEE-CIS (unverified status) |
|---|---|---|---|
| 1 | Real, independently produced fraud labels (not generated by this project) | the whole point of independent validation | real, chargeback-based [S]/[M] |
| 2 | Licence permits the intended use **and publication of results**; terms read and accepted by the owner personally | legal and ethical; competition data are often restricted | **unknown** — read the rules page |
| 3 | A stable entity identifier (customer or account) | histories, sequences, first-fraud events | **absent**; proxy only (card fields) |
| 4 | Entity identifiers documented by the data owner (what a "card" or "account" is) | to know whether a group is a person | not documented in what was read; masked |
| 5 | Event time with a known unit and ordering; ideally a real timestamp | chronological split, time-of-day features, velocity | relative `TransactionDT` [S] |
| 6 | Label definition and delay documented | right-censoring, label propagation | chargeback-based; propagation rule recalled [M] |
| 7 | Enough fraud in the *final* chronological segment (≥ 300 eligible rows, ≥ 300 first-fraud entities) | power; intervals | probably yes for rows (20,663 fraud [S]); entities unknown |
| 8 | Fields that map to the behavioural features (amount, time, device/location, category, login events) | feature mapping | amount, time, coarse address, product class; device only for a subset; no login events |
| 9 | No leakage-prone derived columns, or they are clearly past-only | Vesta `C/D/V` are masked and of unknown timing | present; excluded from the primary arms |
| 10 | Label availability for the final period without a competition submission | final hold-out must be local | train file only; official test labels not public [M] |
| 11 | Size fits the environment (disk, RAM) | 15 GB disk, 15 GB RAM | fits [S]/[M] |
| 12 | Data-protection review: no personal data enters the repository, reports or PDFs | privacy | anonymised/masked; still keep raw data out of git |
| 13 | Redistribution not required for reproducibility | hashes and instructions instead of files | yes |

Decision procedure: if criteria 2, 5, 6, 10 fail → do not use. If 3/4 fail (as here) → proceed only with the proxy-entity design and the claims limited accordingly. Record the outcome of each criterion in `AUDIT0.json` after stage 0.

Candidate fallbacks (all unchecked; all of the synthetic type fail criterion 1 for "real labels", so they would add *independence from this generator*, not realism): a simulated retail card-transaction set with customer and merchant ids; a simulated mobile-money transfer set with account ids; a synthetic tabular-sequence payment set with user and card ids. The 2013 European card dataset has no entity id and masked components, so histories cannot be built.
